# 从材料到判断：总监综合方法与六段回复

适用于 v0.7.1 新研究。吸收用户提供的 Grok 六段式回复所体现的可观察方法；不能恢复或声称知道对方内部思考、完整提示词或私有多 Agent 实现。样例中的市场说法未经本次核验，不预装为事实，也不把其否定语气当成所有 idea 的标准结论。

## 总监要完成的判断

### 1. 先分开“能开发”和“值得成为产品”

把用户的功能设想放回一次真实任务：触发时机 → 准备/授权/摆设备 → 核心操作 → 使用结果 → 下次需要时的选择。问用户省下了什么、又多做了什么；与镜子、表格、搜索、人工等当前办法比较。模型能返回结果，只证明操作链的一步；用户真正采用结果才接近完成任务。

按情境写3–5个必要前提，覆盖痛点是否主要、能否完成任务、真实条件可实现性、重复价值/交换价值、获客竞争。它们不是固定五项问卷：一次性工具可按单次付费判断，不因没有每日留存就否决；个人副业不因规模不够风投级就否决。

### 2. 用事实逐步缩小解释，不由材料数量投票

给每条前提留下支持、反对和未知，主 Agent 必须比较至少一个能解释同样材料的替代解释。例如：教程被点赞，可能因为观赏有趣，而不是用户愿意照着做。工具已经存在，可以削弱“技术新颖”，却同时支持“任务有人尝试解决”；不能自动当作反对需求的证据。

对决定性材料用短的可审计论证：**看到了什么 → 对哪条前提意味着什么 → 仍不能证明什么**。引用可验证的具体产品/用户行为，而不是写“市场拥挤”“有一定风险”。这只是证据摘要，不输出隐藏推理或搜索日志。

历史对手要追问：做了同一任务吗？面向同一人群/商业模式吗？产品和获客条件是否变化？目前仍提供什么？有没有真实使用、付款、退出/增长披露？最早首发不等于市场起点，评论少不等于下载少或营收低，十年没披露规模不等于十年没做大。

大厂选择 B2B 或未把某功能作为 C 端主卖点，可以提出商业解释，但没有业务数据时只能是 E 级推断。真实定价证明报价存在；“有人买单”需要对应交易/客户证据。未取得付费数据写“本轮未找到可核验付费证据”，不用“没人付费”。推断即使很有说服力也不能改标 C。

### 3. 选一个具体失败机制，不列抽象风险

问哪一条前提若不成立，会让当前这条产品/收费路径失效。说明用户会怎样放弃：例如“首次学会后，现有免费工具已足够，因此不再回来”，而不是“留存有风险”。包含触发条件、用户行为、价值损失和决策后果；这是待检验的机制，不是已测得的流失率。

别机械选资料最少、技术最难或最常见的“愿不愿付费”。同时考虑具体反证、影响和改变当前投入决定的能力；强技术限制可以优先，弱需求也可以优先。必须说明相反结果会怎样改变建议。分不清时直接说把握低，不表演“致命缺陷”。

### 4. 测试只证明它实际测到的那一层

优先选能排除关键失败解释的1–2个行动。竞品已经能模拟核心体验时，可先比较现成工具，但必须说明它与原案的关键差别；对竞品不满不等于对原案不满。用真实任务完整操作，不只看生成、点击或30秒演示。

每项声明 `measures`、时间窗、分母/招募条件、是否有主持提醒、观察行为、预设互斥门槛、资源上限和 `cannot_establish`。一项测试只用一个主要决策指标；其他观察可记录，不能与主要门槛混算。门槛是本次小试的建议，不照搬“8–10人、3%、$300”作通用行业基准，也不声称统计显著。

| 实际观察 | 最多能说明 | 不能升级为 |
| --- | --- | --- |
| 主持人带着完成一次任务 | 受引导可用性 | 自主完成、回访 |
| 不提醒时在下一次真实任务主动回来 | 该时间窗的重复使用 | 长期留存、付费 |
| 回答“愿意每月付$5” | 口头价格意愿 | 实际付款 |
| 点订阅/预约，未收款 | 文案/获客响应、购买意向 | 付款、续费 |
| 实际完成一次付费 | 该样本该价格的交换行为 | 持续订阅、市场规模 |

若关键假设是主动回访，广告点击不能作为第二个“回访验证”；它只能是有条件的下一阶段测试。Skill只建议测试，不执行招募、广告、收款或外发。已经足够停止原案时，第五节保留并解释为什么不再测试。

### 5. 相邻方向必须回应原案的失败机制

先说改了哪一个环节、为何可能避开原案问题、已有替代和新增风险。不靠加 AI、加功能或换 B2B 凑“更强”。技术更容易只说明投入可能低，不说明需求更强。B2B买家、销售周期、个人开发者渠道要重新研究。

- `adjacent`：有证据支持相对优势的方向，详细方向须为 `stance=recommended`；来源必须支持该优势，而非仅证明竞品存在。
- `adjacent_hypothesis`：允许一个具体但未验证的设想；必须解释机制、新风险和缺少什么证据，关联 `stance=explore` 的详细方向。明确“可能更强，尚未验证”，不升级评分/投入，不写成已确认市场空白。
- 没找到同类只代表本轮覆盖；不能写“没人做”。没有合理方向时直说没有，不为了第六节硬凑。

## 固定六段式交付

不输出派工过程、材料清单或“已完成调研”开场；直接回复：

**1）一句话结论**：一个紧凑段落，开头就说能不能做/现在值不值得投；点出最重要的现有替代、未证明事项。可再用一行说明当前投入边界。不给“既有机会又有挑战”的空话，不把技术可实现等同可卖。

**2）必须成立的前提**：3–5条编号、具体到本案行为；不默认日活/订阅。原案、发起者目标和内部前提ID不另开表单小节。

**3）证据**：先用一行解释A–E，再分支持/反对。每条包含具体事实、相关产品或行为、等级及一句限制；选择最改变结论的材料，不倾倒整个研究。事实与推断拆条，反证可以比支持多。聊天版在这里附关键来源链接；HTML/完整MD的综述仍无链接，来源在后续详细分支。

**4）最可能杀死它的假设**：只有一个，写完整失败机制和相反结果下的建议。“最可能”是本轮相对判断，不是已知概率；尚未研究时明确无法选定。

**5）下一步最便宜的测试**：通常1–2项，用自然段讲怎么做、看什么、何时通过/失败、不明确时怎么处理、花费上限和不能证明什么；不把每个字段拆成八行表单。

**6）可能更强的相邻方向**：一到两个相对推荐/探索设想，或明确没有；说明改什么、为什么、缺少什么证据和新增风险。当前资源建议归第一节；总分与六维理由放第一节的辅助折叠区，不另加第七节。

聊天回复与 HTML/完整MD综述都固定六节；后续市场/竞品/产品研究依然完整，四章大目录不变。聊天不默认复述全部分支；交付链接放六节之后，评分也可留在报告内。用户要快速结论时压缩证据条数，不能删决定性反证。

## 语义验收反例

- 20人用过一次、竞品有$9.99价格：不能说用户愿意回来并付款。
- 十年产品只有少量文字评论：可以质疑传播/持续价值，不能宣布商业失败。
- 厂商主要做B2B：商业解释标E，并保留渠道/战略等其他解释。
- 用户点“愿意买”：测试测意向，实际付款仍未知；主持提醒的复用不算自主回访。
- 原案因“学会便不用”被质疑：相邻方向要解释为什么仍有重复任务，不能仅说功能更多。
- 没有额外需求证据的检查工具：可以作为探索假设，不得称尚无人做或已证明更优。
- 本来只收一次费用的工具：不以每日留存和续费为必要前提。
